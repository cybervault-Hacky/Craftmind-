THE PRODUCT FLOW

AI → BuildPlan → Minecraft.

Three bounded stages sit between your idea and your world. Each one either succeeds with real data or stops and says why.

01 · AI

You describe, AI designs

Your prompt, plus at most one visual reference, goes directly from your device to the configured Google Gemini model using your own API key. CraftMind operates no AI backend.

02 · BUILDPLAN

CraftMind validates a structured plan

The model must return a BuildPlan v2 document. Bounded parsing and validation check structure, dimensions, operations, blocks, and limits before anything is presented as a build.

03 · MINECRAFT

Your server executes, if you confirm

An optional pinned-LAN Fabric bridge detects the runtime, resolves compatibility, preflights the plan, and asks for a separate final confirmation before placing a single block.

A HUMAN-IN-THE-LOOP WORKFLOW

From a thought
to a plan you can inspect.

CraftMind is an AI-first planner, not a manual block editor. The app implements these steps; a signed release build and end-to-end device verification are still pending.

01

Describe

Write what you want to build. CraftMind sends the request directly to the selected Google Gemini model using the key you provide.

02

Show (optional)

Add one locally checked JPEG, PNG, or WebP image—or a narrowly supported public MP4/WebM file URL. One visual reference at a time.

03

Review the AI plan

Provider output must pass CraftMind's bounded BuildPlan v2 parsing and validation. You inspect and accept a plan before it enters the saved build history.

04

Build only if you choose

An optional compatible Fabric bridge checks the accepted plan on the server. A separate final confirmation is required; reported progress comes from the bridge.
