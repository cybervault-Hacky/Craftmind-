SUPPORT & HELP

Common questions.

Still stuck? The repository's issue tracker is the only support channel this project publishes.

Why can't I download the app yet?

No signed APK has been built, installed, or published. The download button stays disabled until a real, signed artifact exists, and CraftMind will never publish a placeholder APK.

Do I need a Minecraft server to use CraftMind?

No. Planning, review, refinement, and local history all work without a bridge. You only need a bridge if you want an accepted plan executed in a Minecraft world.

Which Minecraft versions are supported?

Minecraft Java 1.20.1 with Fabric Loader 0.16.10 and Fabric API 0.92.2+1.20.1 is the certified production target. It is the only runtime that can be authorized to build.

What about Bedrock or older Java versions?

Bedrock and legacy Java runtimes (1.7.10 and 1.12.2) are recognized and reported as experimental. No runtime certification has been performed for them, so building is unavailable — CraftMind does not approximate a nearby version and never crosses editions.

Do I need my own AI key?

Yes. CraftMind has no AI backend. You save your own Google Gemini API key in Settings, choose a model, and provider errors, quotas, and terms stay between you and Google.

What can I use as a visual reference?

One local JPEG, PNG, or WebP image, or one narrowly supported public MP4/WebM file URL on raw.githubusercontent.com that supports byte ranges. Web pages, playlists, social-video links, redirects, and private sources are not accepted.

Where is my API key stored?

Encrypted with AES-GCM using a key held by the Android Keystore, in app-private no-backup storage. It is never sent to the Minecraft bridge, and the app never displays it back to you in full.

Where are my builds stored?

On your device, in app-private storage, as versioned records with their refinements and diffs. There is no CraftMind account service, no cloud sync, and no telemetry.

Can a build in my world be undone?

No. The app cannot roll back Minecraft block placement. That is why execution requires a server preflight and a separate, explicit confirmation before any block is placed.

Why does a runtime say 'building unavailable'?

Execution passes four gates: authenticated runtime detection, exact adapter selection, compatibility and limit resolution, and a session-bound authorization. Any gate that fails stops the build and states its reason instead of offering a context-free disabled button.

Is there a marketplace, subscription, or account system?

No service, marketplace, subscription, or payment exists in this project, and nothing on this website advertises them. The app ships an account foundation — local mode, encrypted session storage, and honest “sign-in unavailable” states — but there is no account service to sign in to, so no account can be created.

Does the website track me?

No. The site is static HTML and CSS with no analytics, no tracking scripts, and no remote fonts or assets.
